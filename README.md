# Выбор библиотек для вычислительного эксперимента (Шаг 1)

Задача шага 1: выбрать и обосновать библиотеку/библиотеки для (а) интегрирования ОДУ,
(б) получения классических уравнений "из коробки" вместе с реальными измеренными данными,
(в) последующей настройки параметров (шаг 3, Левенберг-Марквардт / градиентные методы).

Ниже — сравнение кандидатов и итоговая рекомендация: не одна библиотека, а **стек из
нескольких**, каждая закрывает свою часть задачи.

---

## 1. Обзор кандидатов

### 1.1 SciPy (`scipy.integrate.solve_ivp`)

- **Роль:** базовый численный решатель ОДУ.
- **Плюсы:** стандарт де-факто, есть везде, отлично документирован, включает явный
  Рунге-Кутту 4(5) порядка (метод `RK45`), проще всего обосновать перед комиссией.
- **Минусы:** не дифференцируем — если нужен градиент по параметрам через сам решатель,
  придётся считать его конечными разностями (медленно, менее точно).
- **Вывод:** хороший базовый/референсный вариант, но не финальный выбор для градиентной
  оптимизации параметров.

### 1.2 diffrax (JAX) / torchdiffeq (PyTorch)

- **Роль:** дифференцируемые решатели ОДУ.
- **Плюсы:** градиент пробрасывается через сам процесс интегрирования (autodiff), что
  напрямую ложится на схему "RK4 + градиентный спуск" из шага 3. diffrax быстрее после
  JIT-компиляции и покрывает больше типов уравнений (ODE/SDE/CDE).
- **Минусы:** компиляция (JIT) может съедать выигрыш при однократном решении с одним
  набором параметров, а не в цикле обучения; экосистема моложе, меньше готовых
  каталогов классических моделей.
- **Вывод:** кандидат №1 для той части эксперимента, где нужен автоматический градиент
  через интегратор.

### 1.3 Julia: DifferentialEquations.jl + ModelingToolkit.jl

- **Роль:** мощная экосистема решателей, в первую очередь для жёстких систем (важно для MHD).
- **Плюсы:** самый широкий выбор солверов, LsqFit.jl для Левенберга-Марквардта,
  Symbolics.jl для символьной работы.
- **Минусы:** сами разработчики честно пишут, что встроенный в LsqFit.jl
  Левенберг-Марквардт слабый и рекомендуют Optim.jl; стыковка с экосистемой SymPy
  (на которой уже построен код Михаила с деревьями) требует моста PyCall/PythonCall —
  дополнительный слой сложности.
- **Вывод:** сильный, но не приоритетный кандидат — стоит держать в уме для MHD/жёстких
  систем, если Python-стека не хватит, но не брать как основной из-за разрыва с SymPy.

### 1.4 dysts (Gilpin, NeurIPS 2021 Datasets Track)

- **Роль:** каталог "готовых" автономных динамических систем.
- **Плюсы:** 135 непрерывных динамических систем (плюс отдельно дискретные отображения),
  правые части уже реализованы и векторизованы; отдельно выложен предвычисленный банк
  траекторий (HuggingFace) — не нужно ничего интегрировать самому, если нужны только
  типовые примеры.
- **Минусы:** это в основном канонические **хаотические аттракторы** (Лоренц, Рёсслер
  и т.п.) — сгенерированные, а не измеренные вживую; то есть закрывает часть "автономные
  ОДУ", но не закрывает требование "реальные данные со ссылкой на источник".
- **Вывод:** используем как источник самих уравнений/траекторий для классов, где реальных
  измерений физически нет или они не нужны (например, Ван-дер-Поль в чистом виде обычно
  и берётся синтетически — это идеализация лампового генератора, а не то, что напрямую
  измеряют).

### 1.5 PyDSTool

- **Роль:** тяжеловесный инструментарий для качественного анализа динамических систем
  (ODE/DAE/гибридные системы, бифуркационный анализ, continuation).
- **Плюсы:** есть библиотека моделей; хорош, если в дальнейшем понадобится анализ
  устойчивости/бифуркаций, а не только подгонка параметров.
- **Минусы:** старый и тяжёлый в установке (жёсткие зависимости от конкретных версий
  numpy/scipy), не заточен под приложенные датасеты реальных измерений, избыточен для
  задачи "уравнение + данные + подгонка параметров".
- **Вывод:** держим как резервный вариант на случай, если в диссертации понадобится
  явный анализ бифуркаций; не основной кандидат для шага 1.

### 1.6 PINTS (Probabilistic Inference on Noisy Time-Series)

- **Роль:** надстройка над любым решателем для подбора параметров модели под зашумлённый
  временной ряд; см. отдельный README (`PINTS_README.md`) с подробным разбором.
- **Плюсы:** готовая модель `LotkaVolterraModel` в модуле `pints.toy` **с приложенными
  реальными данными** (шкуры рыси/зайца, Hudson's Bay Company, 1900–1920) — единственный
  из рассмотренных кандидатов, который прямо из коробки даёт связку "уравнение + измеренные
  данные"; набор методов оптимизации (CMA-ES, Nelder-Mead, PSO) и байесовского вывода
  (MCMC, nested sampling) шире, чем просто Левенберг-Марквардт.
- **Минусы:** не дифференцируем через autodiff; не связан с SymPy напрямую — стыковку с
  деревьями Михаила придётся делать вручную через `sympy.lambdify`; собственный каталог
  toy-моделей скромный (в отличие от dysts).
- **Вывод:** ключевой кандидат для части "модель + реальные данные + подбор параметров",
  особенно для класса Volterra-Lotka.

## 2. Итоговая рекомендация — стек, а не одна библиотека

| Задача | Рекомендуемая библиотека | Почему |
|---|---|---|
| Базовое интегрирование / референс | **SciPy (`solve_ivp`)** | стандарт, проще всего обосновать, используем как baseline |
| Градиент через интегратор (шаг 3, если нужен autodiff) | **diffrax** (или torchdiffeq) | градиент пробрасывается через сам решатель, ложится на RK4+градиентный спуск |
| Жёсткие системы (MHD) при нехватке Python-стека | **Julia: DifferentialEquations.jl** | самый широкий выбор солверов для жёстких систем |
| Каталог автономных ОДУ / синтетические траектории | **dysts** | 135 готовых систем, предвычисленные траектории |
| Уравнение + реальные измеренные данные + подбор параметров | **PINTS** | единственный кандидат с реальными данными "из коробки" (Lotka-Volterra) |
| Качественный анализ (бифуркации), опционально | **PyDSTool** | резерв, если понадобится анализ устойчивости |

**Общее обоснование выбора:** ни одна из библиотек по отдельности не закрывает всю
цепочку "каталог уравнений → реальные данные → дифференцируемый решатель → подбор
параметров". Поэтому предлагается модульная схема: dysts/PINTS дают уравнение и (где
есть) данные, SciPy/diffrax — численное решение, LM/CMA-ES (через PINTS) или
градиентный спуск (через diffrax) — подбор параметров. Это позволяет для каждого
класса уравнений (автономные ОДУ, LCR-контур, Volterra-Lotka, маятник, Ван-дер-Поль,
MHD) явно указать источник как уравнения, так и данных — что было прямым требованием
научрука.
