# PINTS (Probabilistic Inference on Noisy Time-Series)

**Репозиторий:** https://github.com/pints-team/pints
**Документация:** https://pints.readthedocs.io
**Установка:** `pip install pints`
**Лицензия:** BSD 3-clause
**Авторы/происхождение:** группа под руководством D. Gavaghan, M. Clerx и др., Оксфордский университет; библиотека выросла из задач кардиоэлектрофизиологии (подбор параметров моделей ионных каналов сердца под реальные записи потенциала действия).

---

## 1. Что это такое

PINTS — это **не решатель ОДУ**, а надстройка над решателем, заточенная под задачу:
«есть модель, есть зашумлённый временной ряд данных, нужно подобрать параметры модели».

Библиотека абстрагируется на уровень выше самого интегрирования: внутри модели можно
использовать что угодно — `scipy.integrate.odeint`, собственный RK4, обёртку над Julia —
лишь бы был реализован единый интерфейс.

## 2. Ключевая абстракция — `ForwardModel`

Любая модель обязана реализовать всего два метода:

```python
class MyModel(pints.ForwardModel):
    def n_parameters(self):
        # возвращает размерность пространства параметров
        ...

    def simulate(self, parameters, times):
        # возвращает вектор предсказаний модели в заданные моменты времени
        ...
```

Это удобно тем, что можно оставить свой собственный интегратор (например, RK4 из шага 3
эксперимента) и просто обернуть его в этот интерфейс, не переписывая численную часть.

## 3. Методы оптимизации и вывода параметров (шаг 3 эксперимента)

Помимо классического Левенберга-Марквардта, в PINTS есть:

- **Производные-свободные методы**: CMA-ES, Nelder-Mead, PSO, SNES/XNES — работают, когда
  градиент через решатель недоступен (что типично для связки "SymPy-дерево → численный солвер"
  без автодифференцирования).
- **Градиентные методы** — если модель предоставляет якобиан.
- **Байесовский вывод**: адаптивный MCMC, nested sampling — позволяет получить не точечную
  оценку параметров, а апостериорное распределение с доверительными интервалами.

## 4. Модуль `pints.toy` — готовые модели с реальными данными

Ключевая причина, по которой библиотека релевантна для шага 1 (выбор моделей + данных):

- **`pints.toy.LotkaVolterraModel`** — модель хищник-жертва; метод `suggested_values()`
  возвращает **реальные данные** — количество шкур рыси и зайца, собранные компанией
  Hudson's Bay Company в Канаде за 1900–1920 годы (источник указан в докстринге: Howard P.,
  *Modeling basics*, Lecture Notes for Math 442, Texas A&M University, 2009).
- Другие toy-модели пакета: FitzHugh-Nagumo, модели ионных каналов Ходжкина-Хаксли и др.
  (менее приоритетны для текущей задачи, но могут пригодиться при расширении списка классов
  уравнений).

## 5. Ограничения (важно учитывать при выборе)

| Ограничение | Пояснение |
|---|---|
| Нет autodiff "из коробки" | В отличие от diffrax/torchdiffeq, градиент через сам процесс интегрирования не пробрасывается; без явного якобиана доступны только производные-свободные методы или MCMC |
| Нет прямой интеграции с SymPy | Это чисто численный слой поверх готовой функции `simulate`; стыковка с символьными деревьями (код Михаила) потребует ручной обёртки — например, `simulate` реализуется через `sympy.lambdify` от дерева |
| Скромный каталог toy-моделей | В отличие от `dysts` (135 систем), в PINTS всего несколько показательных моделей — зато с приложенными реальными данными, что для dysts не характерно |

## 6. Место PINTS в общей схеме сравнения библиотек

| Библиотека | Роль | Автодифференцирование | Реальные данные "из коробки" |
|---|---|---|---|
| SciPy (`solve_ivp`) | стандартный решатель | нет | нет |
| diffrax (JAX) / torchdiffeq (PyTorch) | дифференцируемый решатель | да | нет |
| Julia: DifferentialEquations.jl + ModelingToolkit.jl | мощная экосистема решателей, жёсткие системы | частично (через SciML) | нет |
| **dysts** | каталог автономных ОДУ (135 систем) | нет | нет (в основном синтетические траектории хаотических систем) |
| **PINTS** | оптимизация/байесовский вывод параметров поверх любого решателя | нет | **да** (Lotka-Volterra + Hudson Bay pelt data) |

## 7. Возможное следующее действие

Обернуть символьное дерево (код Михаила) в `pints.ForwardModel`, подставив в `simulate`
скомпилированную через `sympy.lambdify` функцию правой части ОДУ, и прогнать один из
производных-свободных оптимизаторов (например, CMA-ES) на данных Hudson Bay в качестве
пилотного прогона для шага 3 эксперимента.
